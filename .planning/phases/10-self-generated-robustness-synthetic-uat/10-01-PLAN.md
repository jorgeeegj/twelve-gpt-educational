## 4. Runner Contract (`evals/synthetic_runner.py`)
Specify the runner's public surface (no implementation):

- **Function signature:** `def run(fixture_path: Path, label: str, max_workers: int = 5, skip_judges: bool = False, dry_run: bool = False) -> Path:` returning the run-output directory.
- **CLI:** `uv run python -m evals.synthetic_runner --fixture evals/synthetic/seed_questions.json --label <label> [--workers N] [--skip-judges] [--dry-run]`. `--dry-run` validates fixture only, no agent calls. CLI `--dry-run` maps 1:1 to the `dry_run=True` kwarg.
- **Reuses (do NOT reimplement):**
  - `BasicStatsAgent` from `src.basic_stats.agent` — one instance per question (matches `agent_benchmark.py` pattern; sharing causes 400 errors).
  - `find_violations` from `evals.raw_key_guard`.
  - `judge_faithfulness` from `evals.judges.faithfulness_judge` (when `expected_values` non-null).
  - The `_ask_with_retry` retry pattern from `evals/agent_benchmark.py` (rate-limit backoff).
- **Output directory:** `evals/runs/<YYYY-MM-DD_HH-MM-SS>__synthetic_<label>/` (already gitignored — confirm with `git check-ignore` before commit).
- **Output files — live run (default, `dry_run=False`):**
  - `summary.json` — top-level gate counts + by-category breakdown (with `"dry_run": false`)
  - `results.json` — per-question array, schema in section 5
  - `failure_clusters.json` — written by clusterer (see Plan 04). Always present; `clusters: []` when no failures.
  - `REPORT.md` — Markdown report written by clusterer (see Plan 04). Always present.
- **Output files — dry-run (`dry_run=True` or `--dry-run`):**
  - `summary.json` — minimal contents: `{fixture_path, total_questions, dry_run: true, validation: "ok"}`. No category breakdown.
  - `results.json` — empty JSON array `[]`.
  - **No `failure_clusters.json`, no `REPORT.md`.** The clusterer is NOT invoked in dry-run; the run early-returns after writing the two files above.
- **Exit codes:** 0 on successful run (regardless of failure count); 1 on fixture parse error or runner crash. Failure presence does NOT make exit non-zero — discovery is the goal.

## 5. Per-Question Result Schema (`results.json` entries)
Each entry MUST contain (mirror `agent_benchmark.evaluate_one` output, drop benchmark-only fields, plus two multi-turn fields used by the synthetic runner):

```json
{
  "id": "SYN_<NNN>",
  "category": "<taxonomy enum>",
  "language": "en" | "es",
  "question": "<original, possibly with '|' turn separators>",
  "is_multi_turn": true | false,
  "turn_answers": ["<turn 1 answer>", ...] | null,
  "answer": "<final-turn agent answer or 'ERROR: ...'>",
  "expected_behavior": "answerable" | "refuse" | "ambiguous_clarify",
  "faithfulness_passed": true | false | null,
  "faithfulness_reason": "<string>",
  "raw_key_violations": ["<token>", ...],
  "raw_key_passed": true | false,
  "tool_calls": [...],
  "iterations_used": <int>,
  "hit_max_iterations": <bool>,
  "failure_category": null | "<see section 6>"
}
```

- `is_multi_turn` is `true` iff the original `question` string contained at least one `|` separator.
- `turn_answers` is the per-turn answer array for multi-turn entries; `null` for single-turn.
- `answer` is always the FINAL-turn answer (so guards and faithfulness apply to the answer the user would actually see at the end of the chain).
- `failure_category` is null when the question passed all guards; otherwise set by the clusterer (see section 6 + Plan 04). The clusterer keys on `category` × `failure_category` only — `is_multi_turn` / `turn_answers` are persisted for human review, not clustering.

```json
    }
  ]
}
```

State that initial clustering uses heuristics (Plan 04): group by `category` × `guard_evidence`. LLM-based sub-clustering is deferred.

## 7. Regression Test Workflow
Define when and how a regression test is added to `tests/test_synthetic_regressions.py`:

1. A failure is observed in a run.
2. The cluster has `count >= 1` and is reproducible across two consecutive runs.
3. Author a test in `tests/test_synthetic_regressions.py` that calls `BasicStatsAgent().ask(question)` and asserts the failing condition (e.g. raw-key absence, expected number presence). Use `pytest.mark.xfail` if the production fix is deferred.
4. Reference the cluster's `failure_signature` in the test docstring.
5. The test file MUST exist after Plan 05 even with zero real regressions — it ships with a workflow comment block at the top.
