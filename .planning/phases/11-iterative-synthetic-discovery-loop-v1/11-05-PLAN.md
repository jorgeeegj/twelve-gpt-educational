```python
from __future__ import annotations
import json
from pathlib import Path
from typing import Optional


def run_campaign(campaign_path: Path, label: str, max_workers: int = 1, skip_judges: bool = False) -> Path:
    """Wrap synthetic_runner.run() for a named campaign file.

    Default max_workers=1 mirrors the Phase 10 lesson: BasicStatsAgent init is not
    concurrency-safe under DuckDB write-write conflicts. Callers may override but
    are warned in the docstring.

    Returns the run-output Path produced by synthetic_runner.run().
    """
    # Lazy import to keep this module collectable without DuckDB / openai installed.
    from evals.synthetic_runner import run as _synthetic_run
    return _synthetic_run(
        fixture_path=campaign_path,
        label=label,
        max_workers=max_workers,
        skip_judges=skip_judges,
        dry_run=False,
    )


def _load_clusters(run_dir: Path) -> dict:
    """Load failure_clusters.json from a run directory; raise FileNotFoundError if missing."""


def _index_by_signature(clusters: list[dict]) -> dict[str, dict]:
    """Return {failure_signature: cluster_dict}."""


def _index_question_to_signature(clusters: list[dict]) -> dict[str, str]:
    """Return {question_id: failure_signature} for the first signature seen per id."""


def compare_runs(older_dir: Path, newer_dir: Path) -> dict:
    """Classify cluster differences between two run directories.

    Returns dict matching 11-SPEC.md §7:
      {
        "older_run": str,
        "newer_run": str,
        "repeated":     [{"signature": str, "question_ids": [str]}],
        "disappeared":  [{"signature": str, "question_ids": [str]}],
        "mutated":      [{"question_id": str, "older_signature": str, "newer_signature": str}],
        "new":          [{"signature": str, "question_ids": [str]}],
      }

    Definitions (11-SPEC.md §7):
      - repeated: same failure_signature in both, with at least one shared question_id.
      - disappeared: signature in older, absent in newer.
      - mutated: a question_id that flipped pass→fail or fail→pass between runs,
                 OR same question_id whose failing signature changed.
      - new: signature only in newer.
    """


def write_diff(diff: dict, newer_dir: Path) -> Path:
    """Write `diff_against_<older_run>.json` to newer_dir.

    Returns the path written.
    """
```

Constraints:
- `synthetic_runner` is imported lazily inside `run_campaign` so the test suite for compare-runs can run without OpenAI / DuckDB present.
- No `from src.basic_stats.*` imports anywhere in this module.
- `compare_runs` operates purely on JSON inputs — it does not call the agent or the runner.
- The `mutated` bucket distinguishes "pass-to-fail" / "fail-to-pass" by reading both runs' `results.json` (or by inferring from clusters' question_ids — implement whichever is simpler given the cluster shape; document the choice in a docstring comment).
</action>

Required tests:

1. `test_compare_runs_no_failures_in_either` — both runs have empty clusters; result has all 4 buckets empty.
2. `test_repeated_cluster_with_shared_question_id` — same signature in both runs, overlapping `question_ids` → entry in `repeated`.
3. `test_disappeared_cluster` — signature in older only → entry in `disappeared`.
4. `test_new_cluster` — signature in newer only → entry in `new`.
5. `test_mutated_question_id_changed_signature` — same `question_id` failed under different signatures in the two runs → entry in `mutated` with both signatures.
6. `test_mixed_buckets` — runs with at least one entry in each of repeated/disappeared/mutated/new → the result populates all four lists correctly.
7. `test_write_diff_writes_named_file` — `write_diff(diff, newer_dir)` writes a file named `diff_against_<older_run_basename>.json` and the file content round-trips through `json.loads`.
8. `test_run_campaign_does_not_import_synthetic_runner_at_module_load` — verify by inspecting `iteration_runner` AST or by checking that importing `evals.discovery.iteration_runner` succeeds without `evals.synthetic_runner` being imported (uses `sys.modules` check).

The test suite must NOT invoke the live runner. `run_campaign` itself is NOT exercised end-to-end in this plan's tests (it would require credentials + DuckDB); it is exercised live in Plan 11-07.

The test file MUST NOT import `BasicStatsAgent`.
