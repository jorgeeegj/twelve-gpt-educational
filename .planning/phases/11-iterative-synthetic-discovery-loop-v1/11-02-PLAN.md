Implement the durable file-based failure-memory backlog declared in `11-SPEC.md` §3 — JSON storage + Python helper module providing idempotent append/update/lookup. This is the system's persistent memory of discovered clusters across runs.

### Task 2 — Implement `evals/discovery/failure_backlog.py`

<read_first>

- evals/synthetic_clusterer.py (cluster dict shape)

<action>
Create `evals/discovery/failure_backlog.py` exposing exactly the following public functions:

```python
from __future__ import annotations
import json
from pathlib import Path

DEFAULT_BACKLOG_PATH = Path(__file__).parent / "failure_backlog.json"
_SAMPLE_TRUNC = 200  # mirrors synthetic_clusterer._SAMPLE_TRUNC

def load_backlog(path: Path = DEFAULT_BACKLOG_PATH) -> dict:
    """Read and return the backlog dict. Raises ValueError on schema mismatch."""

def save_backlog(backlog: dict, path: Path = DEFAULT_BACKLOG_PATH) -> None:
    """Write backlog to disk with stable key order (sort_keys=False, indent=2)."""

def find_by_signature(backlog: dict, failure_signature: str) -> dict | None:
    """Return the entry with matching failure_signature, or None."""

def append_or_update(backlog: dict, cluster: dict, run_id: str) -> dict:
    """Idempotent insert/update. Returns the modified backlog (in-place mutation also performed).

    Rules per 11-SPEC.md §3:
      - If cluster.failure_signature exists in backlog: bump seen_count, update
        last_seen_run_id, set-union question_ids, append AT MOST one new
        sample_answer (truncated to 200 chars).
      - If not: insert new entry with monotonic id BACKLOG_<NNN>, first_seen_run_id=last_seen_run_id=run_id,
        seen_count=1, status='open', recommended_action=None, promoted_to=None,
        linked_campaign=None, diagnosis='', notes=None.
    """

def next_id(backlog: dict) -> str:
    """Return the next monotonic id 'BACKLOG_<NNN>' (one greater than the max in entries)."""
```

Constraints:
- No imports from `src.basic_stats.*` (zero production-code coupling).
- No OpenAI / network calls.
- All file I/O via `pathlib.Path`.
- IDs are formatted as `BACKLOG_001`, `BACKLOG_002`, ... (zero-padded to 3 digits).
</action>

### Task 3 — Implement `tests/test_failure_backlog.py`

<read_first>
- evals/discovery/failure_backlog.py
- .planning/phases/11-iterative-synthetic-discovery-loop-v1/11-SPEC.md (§3)
</read_first>

<action>
Create `tests/test_failure_backlog.py` with at least the following 6 test functions, using `tmp_path` for isolation:

1. `test_load_empty_backlog` — round-trip the seed file; assert version == 1 and entries == [].
2. `test_append_inserts_new_entry` — given a synthetic cluster dict, `append_or_update` adds an entry with `id="BACKLOG_001"`, `seen_count=1`, `first_seen_run_id == last_seen_run_id`, `status="open"`.
3. `test_append_idempotent_on_same_signature` — calling `append_or_update` twice with the same cluster + same `run_id` produces a backlog with one entry, `seen_count=2`, `last_seen_run_id == run_id`. (Note: §3 says "incremented on every reappearance" — same-run-id reappearance still bumps the counter; the SPEC's wording does not exclude this.)
4. `test_append_updates_on_new_run` — same cluster, different run_id → `seen_count=2`, `last_seen_run_id` updated to the new run, `first_seen_run_id` unchanged.
5. `test_append_unions_question_ids` — second cluster has overlapping + new `question_ids`; the entry's `question_ids` is the set-union, sorted.
6. `test_find_by_signature_returns_none_for_unknown` — lookup of a signature not present returns `None`.

Each test seeds an isolated `failure_backlog.json` under `tmp_path` and uses the `path=` kwarg to scope I/O to the temp directory.

A helper `_make_cluster(signature: str, question_ids: list[str], answer: str = "...")` is acceptable for DRY.

The test file MUST NOT import `BasicStatsAgent` or DuckDB.
</action>
